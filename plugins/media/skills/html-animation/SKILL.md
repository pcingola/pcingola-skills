# HTML Animation

An animation is a folder that plays in any browser from `index.html`, offline and from `file://`. It has chapters in
order, each with a duration in seconds. A fixed player (`player.js`) owns time: every frame, during playback too, is a
seek of the visible chapter's paused timeline, so the frame at `t` is the same however it was reached. The user
watches and comments in the editor page (`/animate <folder>`); each comment arrives as a prompt that names this skill.

```bash
${CLAUDE_SKILL_DIR}/scripts/html-animation.sh init <folder> --lib gsap|anime|motion [--size 16:9|9:16|1:1|4:5] [--title T] [--with d3,three]
${CLAUDE_SKILL_DIR}/scripts/html-animation.sh add-chapter <folder> <id> --duration S [--title T]
${CLAUDE_SKILL_DIR}/scripts/html-animation.sh build <folder>
${CLAUDE_SKILL_DIR}/scripts/html-animation.sh validate <folder>
${CLAUDE_SKILL_DIR}/scripts/html-animation.sh still <folder> --at T [--mark point:X,Y | rect:X,Y,W,H] [--out PNG]
${CLAUDE_SKILL_DIR}/scripts/html-animation.sh stills <folder> --at T1,T2,... [--outdir DIR]
${CLAUDE_SKILL_DIR}/scripts/html-animation.sh snapshot <folder>
${CLAUDE_SKILL_DIR}/scripts/html-animation.sh install-browser
```

Every command prints JSON on stdout and errors on stderr, and exits non-zero on failure.

| Command | Result |
|---|---|
| `init` | Creates the folder with `player.js`, `lib/` (the timing library, plus d3 and three.js with `--with`), `animation.json` with no chapters and `content.json` `{}`. On an existing folder it copies the current `player.js` and adds the `--with` libraries; content stays. The timing library of a folder never changes. |
| `add-chapter` | Appends the chapter to `animation.json`, writes an empty `chapters/<id>.html` and a stub `chapters/<id>.js` for the folder's library. Ids: lowercase letters, digits and `-`, starting with a letter. |
| `build` | Writes `index.html`: every chapter's html inline, `content.json` inline, script tags for `lib/`, `player.js` and the chapter scripts. Never edit `index.html` by hand. |
| `validate` | `{ok, errors: [{file, line, rule, message}]}`, exit 1 on any error. Rules: `references/determinism.md`. |
| `still` | PNG of the frame at `T` seconds at stage size, from headless Chromium; with `--mark`, a red ring (point) or red rectangle drawn on it in stage pixels. Default `<folder>/stills/t<T>.png`. Prints `{png, t, warnings}`; fails with the page's JavaScript errors. |
| `stills` | Several frames in one browser session. Default `<folder>/stills/t<T>.png`. |
| `snapshot` | Copies `animation.json`, `content.json` and `chapters/` into the next `v<N>/`; prints `{version}`. |
| `install-browser` | Installs Chromium under the plugin data directory. The first `still` does it too (about 290 MB). |

## Folder

| Path | Content |
|---|---|
| `animation.json` | `title`, `size`, `width`, `height` (stage pixels: 16:9 is 1920x1080, 9:16 is 1080x1920, 1:1 is 1080x1080, 4:5 is 1080x1350), `fps`, `lib`, `chapters` `[{id, title, duration}]`. Edit `title`, chapter titles and durations here; `add-chapter` adds chapters. |
| `content.json` | Every text, number and colour on screen, as an object. Chapter scripts read it as `ctx.content`. |
| `chapters/<id>.html` | The chapter's elements in their finished state. Every element has an `id` unique across the animation. A `<style>` block for layout is allowed. |
| `chapters/<id>.js` | The chapter's timeline: one `HA.chapter("<id>", function (ctx) { ... })` call. |
| `player.js`, `lib/` | Fixed. Never edited. |
| `index.html` | Generated by `build`. |
| `stills/` | Output of `still` and `stills`. |
| `comments.json`, `marks/`, `v<N>/` | Written by the editor and by `snapshot`. |

Global time `t` belongs to the chapter with `start < t <= start + duration` (`t = 0` to the first chapter), so `t` at a
chapter's end shows that chapter's finished state. `index.html?t=4.5` opens paused at 4.5 s; opened plain it plays
from 0 with a play and scrub bar (space toggles play).

## Chapter script

`build(ctx)` runs once at load. `ctx`: `el(id)` (the element; throws for an unknown id), `root` (the chapter's
`<section id="ch-<id>">`), `content`, `duration` (seconds), `lib`. It fills text from `content`, builds d3 or three.js
drawings, and returns the library's timeline, paused, with local time 0 to `duration`:

- GSAP: `gsap.timeline({ paused: true })`; positions and durations in seconds.
- anime.js 4: `anime.createTimeline({ autoplay: false })`; positions and durations in milliseconds.
- Motion: `Motion.animate(sequence)`; `at` and `duration` in seconds.

A timeline longer than the chapter is cut at the chapter's end, and `still` lists it in `warnings`. Patterns for
titles, flat charts, three.js scenes and each library are in `references/chapters.md`. `HA.random(seed)` returns a
seeded generator for values that must look random.

## Make an animation

1. Ask nothing the brief answers. Pick the size from where it plays (16:9 for a screen, 9:16 for a phone).
2. `init` with the library the user named, else `gsap`, and `--with d3` for charts, `--with three` for 3D.
3. `add-chapter` for each chapter. Write `content.json` first, then each chapter's html and script.
4. For a chart or diagram, follow `references/motion-rules.md`. For 3D, follow `references/three.md`.
5. `build`, then `validate`. Fix every error and repeat until `ok` is true.
6. `stills` at the middle and the end of each chapter; Read the PNGs and fix what looks wrong (overlaps, text off
   stage, empty frames).
7. Report the folder, `index.html`, and that `/animate <folder>` opens the editor.

## Handle an editor comment

A prompt from the editor carries the folder, the comment id, `t`, the chapter, the mark, the element ids under the
mark and the PNG of the frame with the mark. Follow `references/comments.md`.
